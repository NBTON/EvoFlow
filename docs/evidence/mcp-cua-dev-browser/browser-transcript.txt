- `code: browser_endpoint_owner_mismatch`
- message: *"the isolated browser profile endpoint did not match live loopback socket ownership"*

A second identical call was treated as an idempotent replay of the already-handled action, so no new attempt was made and no browser endpoint was established.

**2. The native fallback path is also unreachable**

The refusal points to the native/accessibility route, but that route needs an exact `(pid, window_id)` pair. Every attempt to obtain one was blocked by policy:

- `list_windows()` (unfiltered) → `policy_denied: "Use the prepared browser PID."`
- `list_windows(app="chrome")` → `policy_denied: "Use the prepared browser PID."`

Since `browser_prepare` never produced a prepared PID, there is no PID I'm permitted to enumerate with, and the desktop `list_windows`/`get_window_state` surface requires a concrete `pid` argument. The only app launch I have available is the Calculator AUMID — there is no callable tool here to launch Chrome/Edge/Brave directly, so I can't bootstrap a browser window to bind against either.

I then read the bundled `browser` guide to check for a documented recovery path for this specific refusal. It documents recovery for `browser_requires_setup`, `browser_consent_required`, `browser_binding_ambiguous`, `browser_ref_stale`, `browser_action_unavailable`, and `browser_input_trust_unavailable` — but not for `browser_endpoint_owner_mismatch`, so no approved workaround exists.
